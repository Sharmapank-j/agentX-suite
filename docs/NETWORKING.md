# AgentX Serve — Cross-Network & Tunneling Guide (v1.0.0)

**Architecture:** Edge HTTP Gateway + WebRTC P2P Direct DataChannel + In-App Reverse Tunnel  
**Target Applications:** AgentX (`:app`), AgentX Medical (`:medical`), AgentX Serve (`:admin`)  

---

## 1. Network Topology Overview

AgentX Suite supports three distinct networking layers for connecting client devices to an edge inference host:

```
+-------------------------------------------------------------------------+
|                              LAYER 1: LAN                               |
|   Local Wi-Fi subnet (192.168.x.x / 10.x.x.x). Direct HTTP / SSE        |
|   Discovery: Network Service Discovery (mDNS / NSD "_agentx-serve._tcp")|
+-------------------------------------------------------------------------+
                                    │
                                    ▼
+-------------------------------------------------------------------------+
|                     LAYER 2: WEBRTC DIRECT P2P                          |
|   Direct UDP socket hole-punching via Google STUN servers.              |
|   Signaling: 6-Digit Cloud Rendezvous Broker (Zero-Relay Streaming).    |
+-------------------------------------------------------------------------+
                                    │
                                    ▼
+-------------------------------------------------------------------------+
|                  LAYER 3: IN-APP REVERSE TUNNEL                         |
|   Outbound SSH/TLS tunnel to public broker (Pinggy / Cloudflare / ngrok)|
|   Exposes live public HTTPS URL with end-to-end token encryption.       |
+-------------------------------------------------------------------------+
```

---

## 2. 6-Digit Cloud Rendezvous & Pairing Workflow

When operating across different cellular or Wi-Fi networks (e.g. Server on 5G, Client on home Wi-Fi), traditional LAN discovery cannot bridge NAT boundaries.

1. **Server Initialization**:
   - AgentX Serve generates a cryptographically secure 6-digit session code (e.g. `839-201`).
   - The server publishes its active base URL, public encryption key, and STUN candidate profile to the ephemeral rendezvous broker.
2. **Client Pairing**:
   - In AgentX or AgentX Medical, tap **Connect to AgentX Serve**.
   - Enter the 6-digit code or scan the on-screen QR code generated by the server.
   - The client fetches the server session profile, verifies the certificate fingerprint, and establishes the connection.

---

## 3. WebRTC P2P Direct DataChannel

For ultra-low latency token streaming without routing inference tokens through any third-party relay:
- **ICE Candidate Exchange**: Handled seamlessly during the initial 6-digit handshake.
- **DataChannel**: Direct peer-to-peer UDP socket using SCTP/DTLS.
- **Failover**: If carrier CGNAT blocks direct UDP traversal, the client gracefully falls back to the in-app reverse tunnel HTTPS/SSE stream.

---

## 4. In-App Reverse Tunnel Configuration

AgentX Serve embeds a pure-Kotlin reverse-proxy tunnel client inside `TunnelManager`:
1. Navigate to **Server Settings** in AgentX Serve.
2. Select your preferred tunnel provider:
   - **Pinggy** (`a.pinggy.io` via SSH reverse port forwarding)
   - **Cloudflare Quick Tunnels**
   - **ngrok**
3. Toggle **Enable Public Remote Access**.
4. The live public HTTPS endpoint (e.g. `https://xxxx.a.pinggy.link/v1`) is automatically displayed and embedded in the pairing QR code.

---

## 5. Security & Zero-Trust Access Control

- **API Key Enforcement**: Every request to `/v1/chat/completions` or `/v1/models` requires `Authorization: Bearer <API_KEY>`.
- **Local IP Restriction**: By default, the Ktor engine binds to `127.0.0.1`. Binding to `0.0.0.0` (all interfaces) requires explicit user approval on the server dashboard.
- **Rate Limiting & Backpressure**: If device battery temperature exceeds 42°C, the server returns HTTP 429 with `Retry-After: 5` to protect hardware integrity.
